Credit Default Scorecard¶

Building a credit risk scorecard the way a lender actually builds one.

The goal is not to maximise a leaderboard metric. It is to produce a model a credit committee can approve: one where every point of the score can be explained to a declined applicant, where the cut-off is chosen against the real cost of being wrong, and where no protected attribute enters the decision.

Data: Statlog (German Credit), UC Irvine Machine Learning Repository — 1,000 real loan applications, 20 attributes, labelled good or bad.

The dataset ships with a cost matrix, and it is asymmetric: lending to a bad applicant costs five times as much as declining a good one. Almost every published analysis of this data ignores that and reports accuracy. Accuracy is the wrong metric when the two errors cost different amounts, and this notebook uses the documented 5:1 ratio to pick the cut-off instead.

Approach¶

Step Why
Drop protected attributes Sex and foreign-worker status are unlawful inputs to a lending decision
Weight of Evidence binning Makes every feature monotonic in log-odds and handles non-linearity without losing interpretability
Information Value screening Standard scorecard feature selection
Logistic regression on WOE The regulator-friendly model; coefficients convert directly into points
Gradient boosting benchmark To measure what interpretability actually costs in AUC
KS, gains, calibration How a risk team reads a model, rather than accuracy
Cost-based cut-off Uses the documented 5:1 matrix

A note on what we are not allowed to use¶

personal_status_sex encodes the applicant's sex. foreign_worker is a proxy for national origin. In the United States the Equal Credit Opportunity Act prohibits both as inputs to a credit decision; the EU Consumer Credit Directive and most other regimes say the same. They are dropped here before any modelling.

This costs a little predictive power. That is the correct trade, and a model that keeps them is not deployable no matter how well it scores.

3. Weight of Evidence and Information Value¶

For each bin, Weight of Evidence is the log ratio of the share of goods to the share of bads:

$$WOE_i = \ln\!\left(\frac{\text{good}_i / \text{good}_{total}}{\text{bad}_i / \text{bad}_{total}}\right)$$

Two things make this the industry default. It re-expresses every attribute, numeric or categorical, on a single log-odds scale, so a logistic regression fitted on WOE has coefficients that are directly comparable and convert cleanly into points. And it absorbs non-linearity — the relationship between age and risk does not have to be a straight line, it only has to be captured by the bins.

Information Value sums the gap across bins and gives one number per attribute:

$$IV = \sum_i \left(\frac{\text{good}_i}{\text{good}_{total}} - \frac{\text{bad}_i}{\text{bad}_{total}}\right) \times WOE_i$$

The conventional reading: below 0.02 is useless, 0.02–0.1 weak, 0.1–0.3 medium, 0.3–0.5 strong, and above 0.5 is suspicious — usually a sign the attribute encodes the outcome rather than predicting it.

def make_bins(s, y, max_bins=5, min_frac=0.05):
    """Quantile bins for numerics, categories as-is. Rare levels are merged into
    'other': a bin with three applicants produces a WOE driven by noise."""
    if pd.api.types.is_numeric_dtype(s) and s.nunique() > 8:
        for q in range(max_bins, 1, -1):
            b = pd.qcut(s, q, duplicates='drop')
            if b.value_counts(normalize=True).min() >= min_frac:
                return b.astype(str), ('num', b.cat.categories)
        b = pd.qcut(s, 2, duplicates='drop')
        return b.astype(str), ('num', b.cat.categories)
    vc = s.value_counts(normalize=True)
    keep = set(vc[vc >= min_frac].index)
    return s.where(s.isin(keep), 'other').astype(str), ('cat', keep)

def woe_table(binned, y):
    t = pd.crosstab(binned, y).rename(columns={0:'good', 1:'bad'})
    for c in ('good','bad'):
        if c not in t: t[c] = 0
    # 0.5 correction keeps an empty cell from sending WOE to infinity
    t['good_pct'] = (t['good'] + 0.5) / (t['good'].sum() + 0.5*len(t))
    t['bad_pct']  = (t['bad']  + 0.5) / (t['bad'].sum()  + 0.5*len(t))
    t['woe'] = np.log(t['good_pct'] / t['bad_pct'])
    t['iv']  = (t['good_pct'] - t['bad_pct']) * t['woe']
    t['n'] = t['good'] + t['bad']
    t['bad_rate'] = t['bad'] / t['n']
    return t

bin_spec, woe_maps, iv_rows = {}, {}, []
for c in X_tr.columns:
    b, spec = make_bins(X_tr[c], y_tr)
    tab = woe_table(b, y_tr)
    bin_spec[c] = spec
    woe_maps[c] = tab['woe'].to_dict()
    iv_rows.append({'attribute': c, 'IV': tab['iv'].sum(), 'bins': len(tab)})

Applicants with no checking account are the safest group, not the riskiest — well ahead of those holding a positive balance. The intuitive reading, that a missing account means a thin file and therefore more risk, is backwards here.

The likely explanation is that in this population people who do not run a checking account at the lending bank are banking elsewhere and are not overdrawn where the bank can see it, whereas a visible balance below 0 DM is exactly what it looks like. Whatever the cause, it is a reminder to bin from the data rather than from intuition — an analyst who imposed a sensible-looking monotonic order on this attribute would have damaged the model.

def apply_woe(frame):
    out = pd.DataFrame(index=frame.index)
    for c in SELECTED:
        kind, spec = bin_spec[c]
        if kind == 'num':
            b = pd.cut(frame[c], bins=pd.IntervalIndex(spec)).astype(str)
        else:
            b = frame[c].where(frame[c].isin(spec), 'other').astype(str)
        # Unseen bin -> WOE 0, i.e. neutral rather than an arbitrary guess
        out[c] = b.map(woe_maps[c]).fillna(0.0).astype(float)
    return out

5. What does interpretability cost?¶

A scorecard is worth having only if the accuracy given up is small. Gradient boosting is the honest comparison — it sees the raw attributes with no binning and no monotonic constraint.

Gradient boosting            test AUC 0.758

Difference: -0.021 AUC

The scorecard wins. Not by much, but the direction is the point: binning into Weight of Evidence gave up nothing to a gradient booster with full access to the raw attributes.

That is not a general result, it is a consequence of this dataset. Seven hundred training rows is far too few for a tree ensemble to find real interactions, so most of what it learns past the main effects is noise, while WOE binning acts as heavy regularisation and throws that noise away. On a book of a hundred thousand applications the ordering would very likely reverse.

The useful conclusion is narrower and still worth having: on a small book, the interpretable model is not a compromise. The argument for a scorecard here is not "worth the accuracy trade-off" — there is no trade-off to make.

6. How a risk team reads the model¶

AUC is a summary. These four are what actually get discussed.

KS — the widest gap between the cumulative good and bad distributions. It answers "how well does the score pull the two populations apart", and it names the score where the separation is greatest.

Gains — if we decline the riskiest decile, what share of all bad loans do we avoid? This is the chart that decides whether a model is worth deploying.

Calibration — does a predicted 20% actually default 20% of the time? Ranking is enough for accept/decline, but pricing and provisioning need the level to be right too.

def ks_stat(y_true, p):
    o = np.argsort(p)
    yy = np.asarray(y_true)[o]
    cb = np.cumsum(yy) / max(yy.sum(), 1)
    cg = np.cumsum(1-yy) / max((1-yy).sum(), 1)
    i = np.argmax(cg - cb)
    return (cg - cb)[i], np.sort(p)[i], cg, cb

ks, ks_at, cg, cb = ks_stat(y_te, p_te)

7. The scorecard¶

Converting the model into points. The standard scaling fixes two anchors — a reference score at reference odds, and the number of points that doubles the odds (PDO):

$$\text{factor} = \frac{PDO}{\ln 2}, \qquad \text{offset} = \text{score}_0 - \text{factor}\times\ln(\text{odds}_0)$$

$$\text{points}_{ij} = -\left(\beta_i \times WOE_{ij} + \frac{\alpha}{n}\right)\times \text{factor} + \frac{\text{offset}}{n}$$

Here: 600 points at 50:1 good:bad odds, 20 points to double. This is the deliverable — an underwriter reads an applicant's attributes off the table, adds up the points, and compares the total to the cut-off. No model needs to be running for a decision to be explained.

PDO, SCORE0, ODDS0 = 20, 600, 50
factor = PDO/np.log(2); offset = SCORE0 - factor*np.log(ODDS0)
n = len(SELECTED); alpha = logit.intercept_[0]

rows = []
for i, c in enumerate(SELECTED):
    beta = logit.coef_[0][i]
    b, _ = make_bins(X_tr[c], y_tr)
    tab = woe_table(b, y_tr)
    for lvl, r in tab.iterrows():

                     'bad_rate': r['bad_rate'], 'woe': r['woe'],
                     'points': -(beta*r['woe'] + alpha/n)*factor + offset/n})

8. Where to set the cut-off¶

The decision the whole exercise exists to support — and the step most analyses skip by defaulting to a 0.5 threshold.

0.5 is only correct when the two errors cost the same. Here the data documentation says they do not: approving a bad applicant costs 5, declining a good one costs 1. The optimal threshold follows from that ratio, not from convention.

def report(t):
    dec = p_te >= t
    tp = int(((dec)&(y_te==1)).sum()); fp = int(((dec)&(y_te==0)).sum())
    fn = int(((~dec)&(y_te==1)).sum()); tn = int(((~dec)&(y_te==0)).sum())
    return {'threshold':t, 'declined':int(dec.sum()), 'bad caught':tp, 'bad approved':fn,
            'good declined':fp, 'good approved':tn,
            'bad capture':tp/max(tp+fn,1), 'cost':tp*0+fp*C_FP+fn*C_FN}

Moving the cut-off from 0.50 to 0.11 cuts cost by 116 units (42%) on the same model.

The cut-off this produces is not one a lender would ship¶

Taken literally, the cost-optimal threshold declines roughly seven applicants in ten. No lending business survives that, and it is worth being clear about why the number comes out that way.

The cost function only counts the cost of errors. It has no term for the money a good loan earns. Given only a 5:1 penalty and no revenue on the other side of the ledger, the cheapest possible book is one that lends to almost nobody — the optimiser is answering the question it was asked, and the question was incomplete.

A production version prices both sides: expected profit per approved good loan against expected loss given default per approved bad one, which pulls the threshold back up to something the business can run. The 5:1 matrix is still the right correction to the naive 0.5 default, and it is still the step most analyses skip. It is just not the whole objective.

What this shows¶

The cut-off is worth as much as the model. Same predictions, same AUC — moving the threshold to reflect what the errors actually cost removes a material share of the loss, and no amount of additional feature engineering would have found it.

Honest limits. A thousand applications is a small book, so the test set is 300 rows and the confidence interval around that AUC is wide. The data is from 1990s Germany and the economics do not transfer. There is no out-of-time sample, so nothing here speaks to stability — in production the first thing to build is a Population Stability Index against the development sample, because scorecards fail by drifting, not by being wrong on day one.

What I would add next: reject inference, since the book only contains applicants who were approved and the model never sees the ones that were turned away; and a monotonic constraint on age and duration so the bins cannot invert on a small sample.
